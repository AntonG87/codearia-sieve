# Sieve. Исследование перед кодом

Проверено 21.09.2026 по первоисточникам: README и документация каждого
инструмента, бенчмарки авторов, реестр npm. Ничего по памяти.

---

## Куда идём — одним абзацем

Открытый бесплатный инструмент, который ставится одной строкой в агента
(Claude Code, Cursor) и превращает страницу не в «читаемый markdown», а в
**решаемое состояние**: даты датами, числа числами, куски под бюджет с якорями
на источник, и число сэкономленных токенов в каждом ответе. Никакого хостинга,
ключей и тарифов. Модель не нужна ни на одном шаге по умолчанию.

## Кто что уже делает

| Инструмент | Что отдаёт | Даты/числа полями | Куски с токенами | Якоря | Открытость |
|---|---|---|---|---|---|
| Jina Reader | markdown, JSON по схеме через ReaderLM | только через модель | нет | нет | сервис; модели CC-BY-NC |
| Firecrawl | markdown, html, JSON по схеме, скриншоты | только через модель, 4 кредита | нет | нет | сервис, кредиты за страницу |
| Mozilla Readability | очищенный HTML | нет | нет | нет | Apache-2.0, релиз 2025-03 |
| Defuddle | HTML/markdown + метаданные (автор, дата, schema.org) | дата из метаданных | нет | нет | MIT, релиз 2026-09-17 |
| trafilatura (Python) | текст/XML + метаданные | дата через htmldate | нет | нет | Apache-2.0 |
| jev-mcp | судит то, что ему передали | — | требует до 50k символов на поле | — | MIT |

Вывод: столбцы «куски с токенами» и «якоря» пусты у всех. Даты и числа как
поля без модели не делает никто из JS-инструментов. Это и есть наше место.

## Чему учат бенчмарки

**Извлечение основного текста.** Авторы trafilatura меряют 15+ библиотек на
одном наборе. Лучший результат — F 0.924 — даёт не один алгоритм, а
**правила плюс алгоритмические запасные пути**. Readability в одиночку — 0.826.
Goose даёт лучшую точность (0.936), но теряет полноту.

Следствие: наш шаг очистки — это цепочка, а не одна библиотека. Первым идёт
Defuddle (свежий, MIT, понимает schema.org, работает с linkedom); если его
результат пуст или подозрительно короток — Readability как запасной; если и он
пуст — честное предупреждение `no-main-content`, а не тишина.

**Даты.** htmldate на 1000 страниц: быстрый режим F 0.925, расширенный —
F 0.949 за счёт перебора всех кандидатов и снятия неоднозначности. Порядок
источников у него: `meta`/Open Graph в шапке → `time` и подобные элементы
→ эвристики по тексту.

Следствие: дата публикации ищется **сначала в разметке, потом в прозе**.
JSON-LD `datePublished`, `article:published_time`, `<time datetime>` — это
точные значения, их не надо разбирать. Разбор прозы (`parseDate`) — последний
ярус, и он обязан уметь отказаться, потому что именно там живут ошибки.

| Извлечение | defuddle | 0.19.4, 2026-09-17 | MIT, метаданные, живой |
| Запасное извлечение | @mozilla/readability | 0.6.0 | проверен временем |
| HTML → markdown | turndown | 7.2.4, 2026-04 | стандарт де-факто |
| Токены | gpt-tokenizer | 4.0.0, 2026-08 | чистый JS, o200k/cl100k |
| MCP | @modelcontextprotocol/sdk | 1.30.0, 2026-07 | официальный |
| Схемы | zod | 4.6.5, 2026-09 | схемы инструментов MCP |

Про токены — честная оговорка. Токенизатор Jev не опубликован. Считаем через
o200k как приближение, пишем об этом в документации, оставляем `Tokenizer`
сменным. Бюджет кусков берём с запасом ~15% именно из-за этого.

## Что говорит спека MCP

Версия 2025-06-18: результат инструмента может нести `structuredContent` —
JSON-объект, плюс `outputSchema` у инструмента для его проверки. Для
совместимости тот же JSON дублируется текстовым блоком в `content`. Ошибки
выполнения — через `isError: true` внутри результата, а не исключением
протокола. Большие данные можно отдавать ссылкой `resource_link`.

Следствие для нас:

- `state` уходит в `structuredContent` со схемой — агент получает типы, а не
  строку, которую надо парсить;
- ожидаемые исходы (robots, пустая страница) — `isError: false` плюс
  `warnings`, потому что материал всё равно есть;
- у инструмента есть режим `summary` (заголовок, даты, факты, размеры кусков,
  экономия) и `full` (с текстом кусков). Полный state большой страницы может
  съесть контекст агента — ровно то, с чем мы боремся.

## Решения, которые фиксируем

1. **Вход** — размеченное объединение `{kind:'url'}` | `{kind:'html'}`.
2. **Ожидаемые исходы не бросают исключений** — `warnings[]` в ответе.
3. **Порты**: `Fetcher`, `Selector`, `Tokenizer` — интерфейсы в ядре,
   реализации по умолчанию внутри, замена через опции. Тесты идут офлайн.
4. **Детерминизм**: часы и идентификаторы — снаружи; один HTML → один JSON,
   проверяется побайтовым сравнением двух прогонов.
5. **Двумерный бюджет** нарезки: токены под 32k Jev и символы под поля
   jev-mcp. Числа — в конфиге.
6. **Якоря**: `id` элемента → `id` ближайшего заголовка → путь заголовков.
   Хеш текста не используем: это якорь, по которому нельзя перейти.
7. **Метаданные раньше прозы** для дат и заголовка.
8. **Собственный проверочный набор** с измеримым результатом, как у
   trafilatura: доля страниц, где материал сохранён, обёртка снята, дата
   найдена, плюс средняя экономия токенов. Без цифр «работает» не считается.

## Чего не делаем в первой версии

Краулинг по задаче, подписки на изменения, headless-браузер, прокси, вызовы
модели по умолчанию, REST-сервис. Всё это либо стоит денег пользователю, либо
превращает инструмент в платформу.
